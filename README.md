# mbs4-client

SPA client for [mbs4](https://github.com/izderadicka/mbs4) in SvelteKit

**WIP**

## Reader security

The production SPA includes a Content Security Policy generated by SvelteKit.
It permits same-origin application scripts and hashes the inline bootstrap, but
does not permit inline book scripts or `blob:` script sources. Foliate's
blob-backed book frames inherit this policy, including fixed-layout books.
`wasm-unsafe-eval` supports the Piper WebAssembly runtime without allowing
JavaScript `eval`. Do not add `unsafe-inline`, `unsafe-eval`, or `blob:` to
`script-src` to resolve a reader compatibility problem.

Deploy the complete rebuilt frontend, including `index.html`, to apply the fix.
No backend change is required. The policy supplements the server's headers;
it does not replace them or provide separate-origin isolation for book content.
Vite development mode relaxes CSP and is not suitable for opening untrusted books.

Run `pnpm build && pnpm test:security` to test the emitted production policy with
Chromium (install it with `pnpm exec playwright install chromium`, or set
`PLAYWRIGHT_CHROMIUM_EXECUTABLE` to an installed browser). The suite checks SPA
bootstrap, both EPUB layouts, inline and external blob scripts, event handlers,
JavaScript URLs, and synthetic cookie-authenticated requests. Vulnerable controls
verify the same payloads execute without the policy. Text, images, styles,
navigation, and application-installed document event handlers must keep working.
